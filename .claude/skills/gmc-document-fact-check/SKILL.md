# GMC 문서 오타·사실 점검 에이전트

이 스킬은 교회 문서(주보, 예배 순서지, 장례/추모 순서지, 공지문, 설교 원고, 소식지 등) 전반에 사용하는
범용 점검 도구입니다. 두 단계로 점검합니다: (1) 오타·맞춤법, (2) 사실 관계(문서 내부 일관성 + 외부 사실 검색 확인).

## 처리 순서

### 0단계 — 문서 전체 읽기
- 첨부된 파일(PDF, DOCX 등)을 페이지/섹션 단위로 전부 읽는다. 일부만 보고 판단하지 않는다.
- 문서 종류를 먼저 파악한다 (예: 장례 순서지, 주일 예배 순서지, 공지문, 설교문 등). 종류에 따라 4단계 신학 점검 적용 여부가 달라진다.

### 1단계 — 오타 · 맞춤법 점검
- 한글: 띄어쓰기, 조사 오류, 중복 자음/모음, 관용구 오용 등을 점검한다.
- 영어: 철자, 이중 자음/모음 오류(예: shinning→shining), 관용 표현 오용(예: bless→bliss)을 점검한다.
- 찬송가·시편 등 인용 가사/본문이 있으면 원문(표준 찬송가, 개역개정 성경 등)과 대조하여 한 글자라도 다르면 표시한다.
- 사람 이름, 직함(집사/장로/목사 등), 영문 이름 표기가 문서 전체에서 일관되는지 확인한다.

### 2단계 — 문서 내부 일관성(사실) 점검
다음을 반드시 계산/대조하여 검증한다. 사람이 손으로 계산해서 틀리기 쉬운 항목들이다.
- 날짜·요일: 명시된 날짜의 요일이 실제와 맞는지 계산한다 (bash로 date 계산 가능).
- 나이·기간: 생년월일과 사망일/기준일로부터 나이를 재계산한다. 문서에 적힌 나이와 비교한다.
- 성경 구절 번호와 인용문이 실제로 일치하는지 (예: "시편 116:12~15"라고 써놓고 본문은 다른 구절 내용인 경우).
- 찬송가 번호와 제목이 일치하는지 (예: "413장"이라고 써놓고 실제 413장 제목과 다른 경우).
- 문서 내 여러 곳에 등장하는 동일 인물/장소/기관명이 서로 다르게 표기되지 않았는지.
- 제목·소제목과 본문 내용이 실제로 부합하는지.

### 3단계 — 외부 사실 검증 (WebSearch 사용)
문서에 등장하는, 외부에서 검증 가능한 사실은 반드시 웹 검색으로 교차 확인한다.
- 인명·지명·기관명(학교, 회사, 지역 등)의 정확한 표기와 실존 여부.
- 역사적 사건, 날짜, 통계 수치.
- 인용문(성경 외 일반 인용)의 출처와 정확성.
- 검증이 안 되거나 검색으로 확인 불가능한 항목은 "확인 불가"로 명시하고, 추측으로 사실 여부를 단정하지 않는다.
- 각 사실 확인 항목에는 근거 출처를 남긴다 (가능하면 링크).

### 4단계 — 신학적 내용 점검 (신학/설교/성경 인용이 포함된 문서에 한함)
- 성경 인용이 원문 번역(개역개정 등)과 일치하는지 확인한다.
- 신학적 진술이 GMC의 신앙고백(침례교 신앙과 메시지 2000, Baptist Faith & Message 2000)의 틀과 상충되지 않는지 점검한다. 상충 여부가 불확실하면 "확인 필요"로 남기고 단정하지 않는다.
- 이 단계는 장례 순서지처럼 신학적 주장이 거의 없는 문서에는 생략해도 된다. 설교문·교리 관련 공지문에는 반드시 적용한다.

## 출력 형식

결과는 페이지/섹션별로, 아래 세 범주로 나누어 정리한다. 목록/표 형식을 사용해도 좋다.

1. **오타·맞춤법** — 위치, 원문, 수정안
2. **내부 일관성 문제** — 위치, 문제 설명(계산 과정 포함), 수정 방향
3. **외부 사실 확인** — 항목, 검증 결과(확인됨/불일치/확인 불가), 근거 출처

각 항목은 "확정 오류"와 "확인이 필요한 사항(저자에게 재확인 요청)"을 명확히 구분한다. 근거 없이 사실 여부를 단정하지 않는다.

## 주의 사항
- 장례식·추모 문서처럼 민감한 문서는 어조에 유의하여 사실 전달 위주로, 감정적 표현 없이 담백하게 보고한다.
- 확실하지 않은 것은 "모른다"고 명시하고, 확인 방법(웹 검색, 원문 대조 등)을 제안한다.
- 사용자가 요청하면 점검 결과를 반영한 수정본 파일도 만들어 제공한다.
